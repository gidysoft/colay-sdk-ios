# Contributing

Thank you for your interest in contributing. Please use GitHub Issues for bug reports and feature requests.

## Pull requests

The `main` branch is protected: nobody pushes to it directly, and every change goes through a pull request that must pass CI and be approved by a Gidysoft maintainer before it is merged.

1. Fork the repository and create a branch from `main`.
2. Keep each change small and focused; if the public API changes, update the README and CHANGELOG.
3. Run the unit tests and add tests for new behaviour.
4. Follow the platform's official style (Kotlin coding conventions / Swift API Design Guidelines).
5. Describe what you changed and why in the pull request description.

Workflows from first-time contributors run only after a maintainer approves them.

To report a security vulnerability, see [SECURITY.md](SECURITY.md).
